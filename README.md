# 今天吃什么 · 本地做菜 App

> GitHub：https://github.com/tianyoufeng/zuocai-app

一个**纯本地运行**的家常菜决策 App：每天纠结吃什么时，一键随机抽一道菜，
给出成品图预览、食材配料（按份数换算）、分步做法，以及忌口过滤与抽菜记录。

无后端、无账号、无网络请求 —— 双击 `app/index.html` 即可使用。

---

## 一、目录结构

```
zuocai-app/
```

**运行方式**：直接双击 `app/index.html`，或拖进任意浏览器。
窄屏会自动切换为全屏真机模式，桌面端则渲染为 390×844 的手机画布并等比缩放居中。

## 三、技术形态

- **纯静态单页**：原生 HTML / CSS / JavaScript，零依赖、零构建。
- **不拆分文件是刻意的**：方便直接双击运行、方便整份复制给别的窗口或设备。
  如果要改造成 Vite / React 工程，`index.html` 里的分区可以直接对应地拆成模块。
- **数据持久化**：`localStorage`，key = `chishenme.v1`。
  存的是忌口清单、抽菜历史、口味偏好、本周目标。清空缓存即恢复出厂状态。
- **图片**：本地相对路径 `assets/images/*.jpg`。菜品图缺失不会破图，
  会自动降级为暖色渐变占位块。

## 四、已完成的功能

**抽菜核心**
- 加权随机抽取，非纯随机 —— 常吃的菜权重更高，避免「抽来抽去都是同几道」
- 忌口（avoid）参与硬过滤，含忌口食材的菜直接不进候选池
- 抽中后生成「选择理由」文案（按口味偏好、耗时、清淡程度动态拼装）
- 加一道新菜只需在 `DISHES` 里追加一项 + 放一张图，无需改逻辑

**菜品内容**
- 每道菜含：成品图、耗时、难度、热量、口味标签、场景标签
- 食材表按份数换算（`BASE_SERVE = 2` 为基准，1–6 人可调）
- 分步做法，带步骤进度条与上一步 / 下一步

**其他**
- 菜谱库：关键词搜索 + 筛选（全部 / 20分钟快手 / 下饭硬菜 / 清淡少油）
- 我的口味：忌口清单管理、口味偏好、本周目标
- 抽菜记录：历史列表，可一键再抽一次
- 收藏 / 分享按钮、Toast 提示、转场动画、键盘快捷键
- 状态栏时间跟随系统实时更新

## 五、约定与纪律（改代码前请先读）

1. **主色 `#E8703A` 每屏只出现一次** —— 只用在当前屏幕唯一的主动作按钮上。
   这是整个设计稿最核心的视觉规则，多一处就破坏层次。
2. **图标一律内联 SVG，不使用 emoji、不使用图标字体。**
   所有图形画在 24×24 坐标系里（`ic(size, inner)` 统一缩放），换尺寸不会被裁切。
3. **菜名走宋体（`--font-serif`），界面文字走黑体（`--font`）**，两者不能混。
4. **阴影是暖色调**（`rgba(232,112,58,...)`），不是中性黑。改成黑色会立刻显脏。
5. **改动设计令牌时，同步更新 `design/设计规范.md`**，保持代码与文档一致。
6. 渲染新屏幕时，`render()` 里必须给根节点补 `is-active` 类，否则整屏空白。
7. 所有用户输入拼进 HTML 前要过 `esc()`；从 localStorage 读出的数据要过 `sanitize()`。

## 六、下一轮可以做的方向

- **扩充菜谱数据**：目前 8 道，建议先铺到 30–50 道，覆盖更多场景（早餐、汤、面食、一人食）。
- **接入真实图片素材**：`design/source-images/` 是原图，换菜时按同样的压缩流程处理
  （长边约 880px、JPEG q84，10 张约 0.9 MB）。
- **拆分为正式工程**：如果要做成可维护的产品，建议 Vite + React，
  把 `DISHES` 抽成 JSON 数据层，7 个屏幕拆成路由。
- **打包成手机 App**：这套纯前端形态很适合直接封成 APK 安装到手机上，
  或做成 PWA 加到主屏。
- **智能增强**：接一个 LLM 做「按冰箱现有食材推荐」，或按周自动生成采购清单。

具体见 `CHANGELOG.md`。
