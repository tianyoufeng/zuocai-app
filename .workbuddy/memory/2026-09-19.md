### 推送踩坑（重要）
- **单次 push 21MB 被 GitHub 502 打断**：`RPC failed; HTTP 502` +
  `unexpected disconnect while reading sideband packet`。这台机器上行慢，大包一次推必失败。
  设 `http.version=HTTP/1.1` 更糟（44MB 推了 12 分钟毫无进展，只能杀掉）。
- **有效办法：拆小包逐个推** —— 把一次提交拆成「代码与数据」+ 按分类拆的图片提交
  （每包 3~5MB），然后
  `for c in $(git rev-list --reverse <base>..HEAD); do git push origin "$c:refs/heads/main"; done`
  7 个提交逐个推，5 分钟全部成功。
- **`*.apk` 已移出版本控制**：每轮 24MB 二进制会让仓库爆炸，改由 GitHub Releases 分发
  （`gh release create v3.0.0 "dist/chishenme-v3.0.0.apk#中文label" --target main`）。
  gh 传中文 label 正常，**资产名必须保持 ASCII**，实测 23.6MB 上传一次成功。
- **nohup 起的后台 push 会在工具调用结束时被杀**：要让它跑完必须用
  `run_in_background=true` 的受管理后台任务，或在前台一次跑完。

## iOS 真机支持（同日再续）

用户指出「apk 是安卓的安装包吧，苹果手机也需要安装在本地运行的哦」——
明确要**真正的 iOS App**，不是 PWA。

### 做法：不用 Mac 也能编
用 GitHub 的**免费 macOS runner** 跑 Capacitor iOS 构建（`.github/workflows/ios.yml`）：
```
npm i @capacitor/ios → npx cap add ios → npx @capacitor/assets generate --ios
→ npx cap sync ios → xcodebuild（禁用签名）→ 手动打包 Payload → .ipa
```
产物是**未签名 IPA**（33MB），自动挂到 Release + 上传 Artifact。
用户在 Windows 用 **Sideloadly** + 自己的 Apple ID 签名后装进 iPhone。

### 关键细节（下次直接用）
- **`cap add ios` 只能在 macOS 上跑**（要 pod install），Windows 生成不了 ios/ 工程
- 禁用签名三件套：`CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""`
- 未签名 IPA = `mkdir Payload && cp -R .../Release-iphoneos/App.app Payload/ && zip -qry x.ipa Payload`
- **Capacitor 模板默认不锁竖屏、版本号是 1.0/1**。用 `plutil -replace` 改 Info.plist：
  `plutil -replace UISupportedInterfaceOrientations -json '["UIInterfaceOrientationPortrait"]'`，
  同时给 xcodebuild 传 `MARKETING_VERSION=3.1.0 CURRENT_PROJECT_VERSION=31` 双保险
- 全程实测只要 1~2 分钟（macOS runner 上 pod install 很快）

### iOS 的硬限制（必须跟用户讲明白）
- 免费 Apple ID 签名 **7 天后失效**，要用同一台电脑重签（覆盖安装，数据不丢）
- 想免掉重签只能买 Apple 开发者账号（$99/年，走 TestFlight）
- iOS 不允许随意分发的安装包 —— 苹果的规则，绕不过去
