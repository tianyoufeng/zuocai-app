# 配图生成规范（v3.0 · 500 道全配图）

> 本文件给「批量生图」的执行者看。照做即可，生成的原图随后由 `tools/compress_images.py` 自动入库。

## 一、背景与目标

这是一个**纯离线中文做菜 App**，菜谱已扩到 500 道，其中 435 道还没有成品图。
用 ImageGen 为每道菜生成一张**成品实拍风**照片，风格与已有 65 张保持一致
（自然光 / 木桌或素色桌面 / 白瓷盛器 / 俯视或 45° 近景 / 中式家常菜摄影）。

## 二、生成参数（固定，不要改）

用 `ImageGen` 工具，直接调用即可（不需要任何前置授权步骤）。参数：

| 参数 | 值 |
|---|---|
| `prompt` | 见第三节的三段式格式 |
| `size` | `"1024x1024"` |
| `output_dir` | `C:/Users/q2764/WorkBuddy/zuocai-app-更新/_raw` |

## 三、prompt 三段式格式（**必须严格遵守**）

```
{风格前缀}_{菜名}_{画面描述}
```

三段之间用**半角下划线 `_`** 连接。原因：入库脚本靠文件名里的**第二段**匹配菜谱，
格式错了这道菜就认不出、等于白花钱。

1. **第一段 · 风格前缀** —— 按 `cat` 取固定值：

| cat | 风格前缀 |
|---|---|
| jiachangcai | 家常中式菜品实拍照片 |
| tanggeng | 家常中式汤品实拍照片 |
| zhushi | 中式主食实拍照片 |
| liangcai | 中式凉菜实拍照片 |
| zaocan | 中式早餐实拍照片 |
| yexiao | 夜宵美食实拍照片 |
| yuecai | 粤菜实拍照片 |
| chuancai | 川菜实拍照片 |
| xiangcai | 湘菜实拍照片 |

2. **第二段 · 菜名** —— 必须和缺图清单里的 `name` **一字不差**（不能加书名号、不能改写）

3. **第三段 · 画面描述** —— 写这盘菜**长什么样**：主料形态与色泽、配料与点缀、盛器、桌面。
   20~35 字，**里面不要再出现下划线**，也不要出现逗号以外的标点混乱。

**完整示例**（可直接照这个感觉写）：

```
家常中式汤品实拍照片_冬瓜排骨汤_清亮汤色中浮着白玉冬瓜块与酥烂排骨撒葱花白瓷汤碗木桌自然光俯视

中式凉菜实拍照片_拍黄瓜_翠绿黄瓜块淋蒜末香醋红油汁堆在白瓷小碟撒白芝麻清爽近景
中式早餐实拍照片_小米南瓜粥_金黄浓稠小米粥里南瓜块盛在白瓷碗配一小碟咸菜晨光木桌俯视

```

## 四、画面要求

- **必须让这道菜一眼认出来**：颜色、形态、配菜要和菜名以及清单里的 `main`（主要食材）吻合
  - 例：`紫菜蛋花汤` 要看得见紫菜和蛋花；`炸酱面` 要看得见面条和褐色肉酱；`烤冷面` 要看得见卷起来的冷面片
- 分类气质要对：
  - 汤羹 → 汤色清亮或奶白、有汤料浮沉、汤碗盛装
  - 主食 → 面 / 饭 / 饺子 / 饼 的形态要清晰可辨
  - 凉菜 → 清爽、有调味汁光泽、小碟小盘
  - 早餐 → 晨光、暖色、家常器皿
  - 夜宵 → 浓油赤酱、暖光、有宵夜氛围
  - 家常菜 → 油亮下饭、家常感
- **不要出现**：文字、水印、人手、刀叉、西餐摆盘、摆拍道具过多
- 同一批里不要张张雷同：换角度（俯视 / 45°）、换盛器（白瓷盘 / 砂锅 / 汤碗 / 小碟）、换配菜位置都可以

## 五、执行方式

1. **先读缺图清单** `_dev/missing-images.json`，按 `cat` 和序号取自己负责的那一段。
   每条长这样：`{ "id": "laziji", "name": "辣子鸡", "cat": "jiachangcai", "main": "鸡腿肉、干辣椒…", "tags": [...] }`

2. **开工前先查重**（幂等，避免重复花钱）。复制改菜名即可：
   ```bash
   export PATH="/c/Users/q2764/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:$PATH"
   cd "C:/Users/q2764/WorkBuddy/zuocai-app-更新"
   ls _raw | grep -F "辣子鸡"
   ```
   有输出 = 这张已经生成过，**跳过**，不要再生成一次。
   （更快的方式：`ls _raw > /tmp/raw.txt` 然后拿自己的菜名列表逐个比对）

3. **每批并行发 6~8 个 ImageGen 调用**（一条消息里放多个工具调用），收齐结果再发下一批。
   不要一次只发一个，那样太慢。

4. 一路做完自己负责的全部数量，**中途不要问我问题**。

5. 单张生成失败（返回里没有 `localPath`）→ 重试一次；仍失败就记下来，最后一起报告。
   **不要为了失败的那张反复重试超过 2 次。**

6. 全部做完后自查一次：把你负责的菜名列表和 `_raw` 里的文件名比对，确认没有漏。

## 六、报告格式（150 字以内）

- 实际成功生成多少张
- 有没有漏的（列出菜名）
- 有没有失败超过 2 次放弃的
- 有没有发现清单里菜名/prompt 有问题的地方

**不要粘贴 prompt 全文，不要粘贴文件路径列表。**
