# 菜谱数据撰写规范（v3.0 扩容）

> 本文件给「批量新增菜谱」的执行者看。照做即可通过 `tools/validate-data.js` 校验。

把菜谱库从 150 道扩到 **500 道**。每个分类文件是**该分类唯一数据源**：

追加新条目 = 用 Edit 把文件末尾的

```
  }
];
```

替换成

```
  },
  {
```

**⚠️ 用 Edit 追加，不要用 Write 覆盖整个文件。** 覆盖会把已有菜谱弄丢。
**⚠️ 条目之间必须有逗号**（最后一个条目后面不要逗号）。这是最常见的翻车点。

## 三、字段规则（会被脚本逐条校验）

| 字段 | 规则 |
|---|---|
| `id` | 只能含小写字母、数字、连字符（`/^[a-z0-9-]+$/`）；全库唯一；用拼音或英文，如 `donggua-wanzi-tang` |
| `name` | 中文菜名，**全库唯一**（不能和任何分类里已有的重名） |
| `cat` | 必须精确等于所在文件的分类 key（字符串，带引号） |
| `time` | 整数分钟，1~480 |
| `diff` | 只能是 `'简单'` / `'中等'` / `'进阶'` 三者之一 |
| `kcal` | 整数，1~3000，按 2 人份估算 |
| `tags` | 非空数组。只用这几个词：`快手` `下饭` `硬菜` `清淡` `少油` `低脂` `素食` `辣` `甜` `重口` `暖胃` `家常` `养生`。每道选 2~4 个 |
| `ings` | 至少 2 项，每项是 `['食材名', '用量']` 两个字符串 |
| `steps` | 至少 2 步（**本规范要求写 4~6 步**），每步 `{ t, d }` 都非空 |

### 关于 `ings` 的用量写法（重要）

详情页会按人数等比换算用量，换算逻辑是「取用量字符串**开头的阿拉伯数字**乘以倍数」。

- 用量**尽量以阿拉伯数字开头**：`'2 个'`、`'300 g'`、`'1 汤匙'`、`'1.5 茶匙'`
- 无法量化的写 `'适量'`、`'少许'`、`'几滴'`、`'半茶匙'`（这类不会被换算，符合预期）
- 不要写 `'三根'` 这种汉字数字，也不要写 `'2-3 个'` 这种范围

## 四、真实感要求（这个项目最在意的事）

1. 菜必须是**真实存在、真有人吃**的中式菜，不要生造菜名
2. 分量要符合实际（一个人一顿吃多少，油盐酱醋放多少）—— 不要出现「生抽 200 ml」这种
3. 步骤要能**照着做出来**：顺序符合常识（先焯水再炒、先炒香底料再下主料、先调味后收汁）
4. `d` 描述要写**可执行的细节**，不要写空话：
   - ✅ 「锅烧到冒青烟再下油，肉片滑散到变色立刻盛出」
   - ❌ 「把肉炒熟」
   - ✅ 「中火烧 3 分钟，汤汁收到能挂住勺背」
   - ❌ 「收汁即可」
5. 同类菜不要只换名字 —— 每道菜的关键手法、火候、配料搭配要真的有区别
6. `t` 写 4~6 字小标题（如「焯水定色」「爆香底料」「勾芡收汁」）
